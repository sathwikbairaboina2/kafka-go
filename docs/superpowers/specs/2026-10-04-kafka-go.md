Lead: Claude Opus (plan, review). Builder: `sonnet-builder`. Design source:

Where they disagree, this spec wins and the reason is a `Ruling:` line below or an ADR in `docs/adr/`.

## One-line pitch

A single-binary Kafka broker in Go, written on the standard library only, that real clients
(franz-go 1.22.1 and kcat 1.7.1 / librdkafka 1.8.2) produce to, consume from and run consumer groups against,
with a crash-safe segment log and every limit pinned by a test.

## Scope

### In v0.1

1. TCP listener, int32 size-prefixed frames, max frame size, strictly in-order responses per connection.
2. Codec primitives including flexible encodings (uvarint, compact string/array, tagged fields) and zigzag varint/varlong.
3. Exactly these API versions (ADR 0004 and its amendment: ranges, because librdkafka feature detection needs the old minimums). The table in `internal/protocol/versions.go` drives both the ApiVersions
   response and the request gate.

   | API | Key | Versions | Flexible |
   |---|---|---|---|
   | Produce | 0 | 3-7 | no |
   | Fetch | 1 | 4-11 | no |
   | ListOffsets | 2 | 2 | no |
   | Metadata | 3 | 4 | no |
   | OffsetCommit | 8 | 2-7 | no |
   | OffsetFetch | 9 | 1-7 | v6+ |
   | FindCoordinator | 10 | 0-2 | no |
   | JoinGroup | 11 | 0-5 | no |
   | Heartbeat | 12 | 0-3 | no |
   | LeaveGroup | 13 | 0-1 | no |
   | SyncGroup | 14 | 0-3 | no |
   | ApiVersions | 18 | 0-3 | v3 only |

   Evidence (measured 2026-10-04 against `apache/kafka:4.3.1`): kcat 1.7.1 sent ApiVersions v3, Metadata v4,
   Produce v7, Fetch v11, ListOffsets v2, FindCoordinator v2, JoinGroup v5, SyncGroup v3, Heartbeat v3,
   LeaveGroup v1, OffsetCommit v7. franz-go v1.22.1 with `kgo.MaxVersions` capped at exactly this table
   produced, consumed in a group and committed successfully (spike in the planning session).
4. Record batch v2: header validation (magic 2, batchLength, CRC-32C over bytes 21..end), stored verbatim
   with only `baseOffset` rewritten (ADR 0001). Compressed batches are accepted and stored opaquely.
5. Segment log per partition: `.log` + sparse `.index` (8-byte entries every 4096 bytes), roll by size,
   one writer per partition (ADR 0002), recovery that truncates a torn tail of the active segment and rebuilds
   its index, retention by time and by size that never deletes the active segment.
6. Topic metadata in `data/meta/topics.json`, replaced atomically (write tmp, fsync, rename, fsync dir).
   Topics are created by `--topic name:partitions` flags or auto-created on Metadata/Produce (ADR 0008).
7. Consumer groups: FindCoordinator (always self), JoinGroup (v4+ MEMBER_ID_REQUIRED flow), SyncGroup,
   Heartbeat, LeaveGroup, session expiry, OffsetCommit with generation/member checks, OffsetFetch.
   Assignment is computed client-side, as in Kafka; the broker only stores the leader's assignment.
8. Committed offsets in an append-only, CRC-framed file `data/__offsets/commits.log`, replayed on start,
   torn tail truncated.
9. `--fsync always|interval|never` (default `interval`, 50 ms).
10. `kgoctl dump-log <segment.log>` and `kgoctl verify-log <data-dir>` (exit 1 on any violation).
11. Benchmarks: `bench/load` (franz-go load generator) vs Apache Kafka 4.3.1 in the same compose project;
    `bench/crash` (kill -9 loop, ADR 0005).
12. Compat: franz-go tests run in-process under `go test`; kcat round trip and kcat group consume via compose.

### Out of v0.1 (each is a limit in the README)

- Replication, ISR, leader election, KRaft. Single broker, node id 1 (ADR 0003).
- Any API not in the table above: CreateTopics, DeleteTopics, InitProducerId, transactions,
  DescribeTopicPartitions and the CodeCrafters KRaft metadata reader. The README makes no CodeCrafters stage claim.
- Fetch sessions (KIP-227): every fetch is a full fetch and the response always has `session_id = 0`.
- Compaction, SASL/TLS, ACLs, quotas (`throttle_time_ms` is always 0).
- `.timeindex`. ListOffsets with a real timestamp scans batch headers and answers at batch granularity.
- Prometheus `/metrics` (moved to v0.2).
- Zero-copy `sendfile` (Fetch copies bytes with `ReadAt`).
- Power-loss durability claims (ADR 0005).

## Rulings

- Ruling: unknown API key, or an unsupported version of any API other than ApiVersions, closes the connection
  without writing a response (Kafka's behaviour; a reply body for an unknown version is undefined).
  ApiVersions at an unsupported version gets a v0-format body with error 35 and the full key table.
- Ruling (amended during the build): responses use response header v0, except OffsetFetch v6 and v7 which are
  flexible and use header v1. ApiVersions always uses v0 by spec. The server still computes the header version from the table so a
  future flexible API gets header v1.
- Ruling: Produce with `acks=0` writes no response. Later responses on that connection keep request order.
- Ruling: the admin CLI is `kgoctl`, not `kgo`, to avoid confusion with franz-go's `kgo` package.
- Ruling: the offset store is a separate CRC-framed file, not a `__consumer_offsets` partition (the design's
  open question; reuse is v0.2).
- Ruling: the broker never decompresses. `kgoctl dump-log` iterates records only for `compression = none` and
  prints `compressed (codec N), N records` otherwise.
- Ruling: lint is `go vet` + `gofmt`; golangci-lint is not used.
- Ruling: the bench duration is 30 s per run, 3 runs per target, median reported (design said 60 s).
- Ruling: Prometheus metrics, `.timeindex`, CreateTopics and DescribeTopicPartitions move to v0.2.

## Package layout

| Path | Responsibility |
|---|---|
| `internal/protocol` | Reader/Writer primitives, request/response headers, error codes, version table, one file per API with request `Decode` and response `Encode`. |
| `internal/record` | Batch header parse and validation, CRC-32C, `baseOffset` rewrite, `Builder` (tests, tools), record iteration (uncompressed). |
| `internal/storage` | `Segment`, sparse index, `Partition` (multi-segment log, append, read, roll, recovery, retention), `Manager` (topic-partition registry, fsync policy, wakeups). |
| `internal/meta` | `topics.json` store with atomic replace. |
| `internal/group` | Pure group state machine (`Group`), `Coordinator` (locking, timers, blocking replies), `OffsetStore`. |
| `internal/broker` | One handler per API: decode, call storage/meta/group, encode. Implements `server.Handler`. |
| `internal/server` | Listener, framing, per-connection loop, header parsing, version gate. |
| `cmd/kgod` | Broker binary. |
| `cmd/kgoctl` | Offline log tools. |
| `compat/` | franz-go tests against an in-process broker. |
| `bench/load`, `bench/crash`, `bench/report` | Load generator, crash loop, README table printer. |
| `scripts/` | `go.ps1`, `go.sh`, `demo.sh`, `compat-kcat.sh`, `bench.sh`. |

The broker packages (`cmd/kgod`, `cmd/kgoctl`, `internal/...`) import only the standard library. franz-go,
kmsg and rapid appear only in `_test.go` files, `compat/`, and `bench/` (ADR 0007). A gate checks this.

## Invariants and the tests that prove them

| # | Invariant | Test |
|---|---|---|
| 1 | Offsets in a partition are dense and strictly increasing across segment rolls. | `TestAppendOffsetsDense` (rapid) in `internal/storage` |
| 2 | A batch with bad CRC, wrong magic or length mismatch is never appended. | `TestProduceRejectsCorruptBatch` (`internal/broker`), `FuzzParseBatch` (`internal/record`) |
| 3 | An offset acked with `acks=-1` is readable after `kill -9` of the broker process. | `bench/crash` (`TestCrashLoopSmoke` runs 2 iterations in `go test`) |
| 4 | Recovery truncates a torn tail at the first invalid batch and rebuilds the index. | `TestRecoveryTruncatesTornWrite`, `FuzzRecoverSegment` |
| 5 | Sparse index lookup equals a linear scan for every offset. | `TestIndexLookupMatchesScan` (rapid) |
| 6 | Responses on a connection come back in request order with the correlation id echoed. | `TestPipelinedRequestsInOrder` (1,000 pipelined requests, acks=0 produces mixed in) |
| 7 | Unsupported versions never reach a body decoder. | `TestVersionGate` (every key, min-1 and max+1, plus an unknown key) |
| 8 | Retention never deletes the active segment; `logStartOffset` never decreases. | `TestRetentionKeepsActiveSegment` (rapid, fake clock) |
| 9 | OffsetCommit from a stale generation or unknown member is rejected and not persisted. | `TestCommitStaleGenerationRejected`, `TestGroupModel` (rapid state machine) |
| 10 | An oversized frame closes the connection without allocating the claimed size. | `TestOversizedFrameRejected` |
| 11 | Real clients interoperate. | `compat/franzgo_test.go`, `scripts/compat-kcat.sh` |
| 12 | Encoders and decoders agree byte-for-byte with franz-go's kmsg for every supported version. | `*_oracle_test.go` in `internal/protocol` |

## Isolation and environment

- Host ports 5380-5389 only: kgod `5380:9092`, Apache Kafka `5382:9092`. Nothing else is published.
- Compose project name `kafka-go`; container names `kafka-go-kgod`, `kafka-go-kafka`; every `docker run`
  uses `--name kafka-go-<purpose>-<random>` and `--rm`. Network `kafka-go_default`.
- Go runs only in Docker: `golang:1.26` (verified `go1.26.8 linux/amd64`), cache volumes `kafka-go-gomod` and
  `kafka-go-gobuild`.
- Pinned versions checked on 2026-10-04: `github.com/twmb/franz-go v1.22.1` (needs go 1.26.0),
  `github.com/twmb/franz-go/pkg/kmsg v1.14.0`, `pgregory.net/rapid v1.3.0`, `apache/kafka:4.3.1`,
